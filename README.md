# FaceAttend

Система учёта рабочего времени с распознаванием лиц: отметка прихода/ухода через киоск, табель, отпуска, расчёт зарплаты и KPI отделов.

**Стек:** Nuxt 3 (Vue 3 + Nitro), Tailwind CSS, PostgreSQL + Drizzle ORM, `@vladmandic/face-api` (распознавание в браузере).

## Возможности

- **Киоск у входа** (планшет/телефон): отметка без рук — посмотреть в камеру и чуть повернуть голову. Режимы устройства: одна дверь (авто), только вход, только выход. Экран не гаснет.
- **Регистрация лица** по 5 кадрам с проверкой качества и согласованности; дубликаты лиц отклоняются.
- **Главная**: кто сейчас в офисе, опоздавшие, кто ещё не пришёл, кто в отпуске, незакрытые смены, посещаемость за 7 дней.
- **Табель-сетка** «сотрудник × день» с опозданиями, пропусками, отпусками и праздниками; клик по ячейке — исправление или ручная отметка с обязательной причиной (пересчёт опоздания/переработки, запись в журнал). Выгрузка в Excel/CSV.
- **Праздники РК** засеиваются автоматически, переносы и Құрбан айт добавляются в настройках; учитываются в плане дней, зарплате (работа в праздник по выходному коэффициенту) и KPI.
- **Пользователи**: создание руководителей и менеджеров с одноразовым паролем, сброс пароля, отключение.
- **Журнал действий**: входы, отметки, исправления, изменения сотрудников, зарплата.
- Отпуска, расчёт зарплаты, KPI отделов, справочники (отделы, должности, графики).

## Как это работает

```
Киоск (браузер)                                   Сервер (Nitro)                      PostgreSQL
───────────────                                   ──────────────                      ──────────
камера → face-api: детекция, 68 точек,
         128-мерный дескриптор
проверка «живости»: смотреть прямо →
         повернуть голову → снова прямо
POST /api/attendance/checkin ──────────────────►  1. киоск авторизован? (cookie)
  { type, descriptors[2–3 кадра], photo }         2. сравнение 1:N с эталонами ─────► employees.face_descriptor
                                                     (порог, проверка неоднозначности,
                                                      все кадры — один и тот же человек)
                                                  3. время и дата — с сервера (APP_TIMEZONE)
                                                  4. опоздание/переработка по графику ───► attendance
                                                  5. фото → таблица files, событие → audit_log
```

Принципы, которых придерживаются промышленные системы (и этот проект):

- **Сравнивает лица сервер.** Браузер присылает только дескрипторы. Эталоны сотрудников никогда не уходят клиенту, и браузер не может просто сказать «это сотрудник №5».
- **Время отметки ставит сервер**, в часовом поясе организации, а не в часовом поясе сервера (Render работает в UTC).
- **Отмечаться можно только с доверенного устройства.** Админ или руководитель активирует киоск, устройство получает httpOnly-cookie на 180 дней, и его можно отозвать.
- **Проверка «живости»** (liveness). Плоское фото при наклоне сохраняет пропорции лица, а живая голова при повороте — нет. Это защищает от распечатки или фото на телефоне, но **не** от видеозаписи или маски. Для строгих требований нужна серверная PAD-модель (ISO/IEC 30107), например через [CompreFace](https://github.com/exadel-inc/CompreFace).

## Роли

| Роль | Доступ |
|---|---|
| `admin` | всё: справочники, зарплата, настройки, киоски |
| `head` | только сотрудники своего отдела: добавление/редактирование (без оклада), отпуска, табель, зарплата своего отдела |
| `manager` | просмотр табеля и сотрудников (без окладов), заявки на отпуск |

## Запуск локально

```bash
npm install
cp .env.example .env     # указать DATABASE_URL и JWT_SECRET
npm run dev              # http://localhost:3000
```

При первом запуске на пустой базе создаётся пользователь `admin` с паролем из `ADMIN_PASSWORD` (или случайным — он выводится в лог один раз). При первом входе пароль обязательно нужно сменить. Если в существующей базе остались старые стандартные пароли (`admin123`, `head123`, `manager123`), система тоже потребует их сменить.

Таблицы создаются и мигрируются автоматически при старте (`server/db/index.ts`).

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | строка подключения PostgreSQL |
| `JWT_SECRET` | **обязательна в production**, не короче 32 символов |
| `ADMIN_PASSWORD` | пароль первого admin (только для пустой базы) |
| `APP_TIMEZONE` | часовой пояс организации, по умолчанию `Asia/Almaty` |
| `FACE_MATCH_THRESHOLD` | порог евклидова расстояния, по умолчанию `0.45` (меньше — строже) |
| `SEED_DEMO_USERS` | `true` — создать демо-пользователей `head`/`manager` |
| `PGSSL` | `false` — отключить SSL к базе (локальный Postgres при `NODE_ENV=production`) |

## Деплой (Render)

`render.yaml` уже настроен: `JWT_SECRET` генерируется сам, а `DATABASE_URL` и `ADMIN_PASSWORD` задаются в панели Render. Фото хранятся в базе (таблица `files`), потому что диск бесплатного Render очищается при каждом перезапуске.

## Расчёт зарплаты

`salaryRate` — месячный оклад.

- часовая ставка = оклад / (плановые рабочие дни месяца по графику × часов в день)
- обычные часы = за каждый рабочий день min(отработано − переработка, норма дня); обед не оплачивается
- переработка = время после окончания смены по графику × `overtimeCoefficient`
- работа в выходной (день вне графика) = все отработанные часы × `weekendCoefficient`

Ночные смены (уход после полуночи) поддерживаются. Отпускные и праздничные дни пока не учитываются.

## Что можно доработать

- серверная проверка «живости» (PAD) и защита от видеоповтора;
- производственный календарь РК (праздники, переносы);
- расчёт отпускных по среднему заработку, удержания (ИПН, ОПВ);
- миграции через `drizzle-kit` вместо SQL при старте;
- согласие сотрудника на обработку биометрии и срок её хранения (Закон РК «О персональных данных»).
